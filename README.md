# Concrete Crack Detection and Severity Estimation for Campus Infrastructure

A reproducible deep-learning prototype for **binary image classification** of concrete surfaces as Crack or No-Crack. The repository contains a ResNet18 transfer-learning pipeline and a Streamlit image-upload demo.

## Dataset

Use the **Concrete Crack Images for Classification (CCIC), Version 2** dataset by Özgenel (Mendeley Data, DOI: [10.17632/5y9wdsg2zt.2](https://doi.org/10.17632/5y9wdsg2zt.2)). The published dataset contains 40,000 RGB images, with 20,000 images in each class.

The downloaded course archive may contain a nested RAR archive. Extract both archive layers before training. See [DATASET_SETUP.md](DATASET_SETUP.md).

Expected folder layout (folder names are case-sensitive on Linux):

```
data/concrete/
  Negative/
    image_1.jpg
    ...
  Positive/
    image_1.jpg
    ...
```

Do not commit the dataset or extracted images to GitHub. The `data/` folder is ignored by Git.

## Implemented scope and limitations

- Implemented: image preprocessing, ResNet18 transfer-learning classifier, stratified train/validation/test split (70/15/15), checkpoint selection on validation loss, held-out test metrics, and Streamlit inference.
- The CCIC dataset provides image-level Crack/No-Crack labels only. It does **not** provide pixel masks, physical crack dimensions, or expert-rated severity labels.
- This repository does not currently implement validated crack segmentation or structural severity estimation. Do not describe a visual guess or pixel count as an engineering severity rating.
- The classifier is a preliminary screening aid only. Structural safety decisions require qualified civil/structural engineering assessment.
- No accuracy, F1, AUC, or other dataset-level result is claimed in advance. Report only the metrics generated by your own completed held-out test run.

## Setup

Python 3.10 or 3.11 is recommended.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
```

## Train and evaluate

From the repository root:

```bash
python src/train.py --data-dir data/concrete --epochs 10 --batch-size 32
python src/evaluate.py --data-dir data/concrete --checkpoint outputs/best_model.pth
```

The training script saves the best validation-loss checkpoint and training history under `outputs/`. Evaluation writes `outputs/test_metrics.json`. Keep the test set untouched until final evaluation.

## Run the demo

```bash
streamlit run app.py
```

The app requires a trained checkpoint at `outputs/best_model.pth`.
